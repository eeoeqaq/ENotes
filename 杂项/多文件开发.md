 
## 1. 声明和实现的文件组织
==注1：下面代码中ifndef的功能在最后有介绍==
### 头文件 (.h/.hpp)

```cpp
// myclass.h
#ifndef MYCLASS_H
#define MYCLASS_H

class MyClass {
private:
    int data;
    
public:
    // 声明
    MyClass();
    void setData(int value);
    int getData() const;
    
    // 内联函数可以在头文件中实现
    void reset() { data = 0; }
};

// 函数声明
void helperFunction();
extern int globalVariable; // 全局变量声明

#endif
```

### 源文件 (.cpp)
 
```cpp
// myclass.cpp
#include "myclass.h"

// 实现
MyClass::MyClass() : data(0) {}

void MyClass::setData(int value) {
    data = value;
}

int MyClass::getData() const {
    return data;
}

void helperFunction() {
    // 实现
}

int globalVariable = 42; // 全局变量定义
```

### 主文件 (main.cpp)
```cpp
// main.cpp
#include "myclass.h"
#include <iostream>

int main() {
    MyClass obj;
    obj.setData(10);
    std::cout << obj.getData() << std::endl;
    return 0;
}
```

## 2. 主要开发规范

### 文件组织规范
- **头文件保护**：使用 `#ifndef/#define/#endif` 或 `#pragma once`
- **包含顺序**：系统头文件 → 第三方库头文件 → 项目头文件
- **最小包含原则**：只包含必要的头文件

### 命名规范
```cpp
// 常见的命名约定
class MyClass {           // 类名：大驼峰
    int member_variable_; // 成员变量：小写+下划线+后缀_
    void memberFunction(); // 成员函数：小驼峰
};

namespace my_namespace {  // 命名空间：小写+下划线
    const int MAX_SIZE = 100; // 常量：大写+下划线
    void global_function();   // 函数：小写+下划线
}
```


### 代码风格规范
```cpp
// 一致的缩进和空格
void properlyFormattedFunction(int param1, const std::string& param2) {
    if (condition) {
        doSomething();
    } else {
        doSomethingElse();
    }
    
    // 有意义的变量名
    int user_count = getUsers();
    auto result = calculateFinalScore();
}
```

`#ifndef`（if not defined）是**头文件保护**（Header Guard）或**包含保护**（Include Guard），用于防止头文件被重复包含。

## 为什么需要头文件保护？

### 问题场景
```cpp
// a.h
class A {
    // 类定义
};

// b.h
#include "a.h"  // 第一次包含a.h
class B {
    A a;
};

// main.cpp
#include "a.h"   // 第二次包含a.h - 错误！
#include "b.h"   // 这里也会间接包含a.h

int main() {
    return 0;
}
```

这会编译错误，因为 `class A` 被重复定义了。

## 解决方案：头文件保护

### 传统方式 `#ifndef/#define/#endif`
```cpp
// myclass.h
#ifndef MYCLASS_H     // 如果MYCLASS_H未定义
#define MYCLASS_H     // 则定义MYCLASS_H，并编译下面的内容

class MyClass {
    // 类定义
};

#endif               // 结束条件编译
```

### 工作流程
1. **第一次包含**：`MYCLASS_H` 未定义 → 执行 `#define` 并编译类定义
2. **后续包含**：`MYCLASS_H` 已定义 → 跳过整个内容

### 现代方式 `#pragma once`
```cpp
// myclass.h
#pragma once         // 编译器指令：此文件只包含一次

class MyClass {
    // 类定义
};
```

## 两种方式对比

### `#ifndef/#define/#endif`
**优点：**
- C++标准支持，所有编译器都兼容
- 可以自定义宏名

**缺点：**
- 需要手动确保宏名唯一
- 代码稍显冗长

```cpp
// 确保唯一性的常见做法
#ifndef PROJECTNAME_FILENAME_H
#define PROJECTNAME_FILENAME_H
// ...
#endif
```

### `#pragma once`
**优点：**
- 简洁明了
- 编译器优化，可能更快
- 不会出现宏名冲突

**缺点：**
- 非C++标准（但几乎所有现代编译器都支持）
- 在符号链接或硬链接情况下可能有问题

## 实际应用示例

### 复杂的头文件包含情况
```cpp
// utils.h
#ifndef UTILS_H
#define UTILS_H

#include <string>

std::string formatString(const std::string& input);
double calculateAverage(const std::vector<double>& values);

#endif

// logger.h  
#ifndef LOGGER_H
#define LOGGER_H

#include "utils.h"  // 安全包含，即使被多个文件包含也不会重复

class Logger {
public:
    void log(const std::string& message);
};

#endif

// main.cpp
#include "utils.h"   // 第一次包含 - 编译
#include "logger.h"  // 间接包含utils.h - 跳过重复内容
#include "utils.h"   // 第二次直接包含 - 跳过重复内容
                     // 没有头文件保护会编译错误！
```

## 最佳实践

1. **始终使用头文件保护** - 即使是小型项目
2. **选择一种风格并保持一致性**
3. **宏名要唯一** - 通常使用 `项目名_文件名_H`
4. **放在文件开头** - 在任何代码之前

```cpp
// 好的示例：PROJECT_MODULE_FILENAME_H
#ifndef MYGAME_GRAPHICS_RENDERER_H
#define MYGAME_GRAPHICS_RENDERER_H

// 头文件内容...

#endif
```

头文件保护是C++开发中的基本但至关重要的实践，可以避免很多难以调试的重定义错误。
